# Oath Wallet 5.0.3 (105) — prerelease

This is a GitHub source prerelease. Build 105 has not been uploaded to App Store
Connect or submitted for review. The Apple-approved release remains 5.0.2 (104).

## Prerelease update — 6 November 2026, revision 5

Asset rows now show the unit price below the asset name, with the wallet's fiat
value and native quantity together. Unpriced assets show “Price Untracked”; tapping
it explains market-data coverage without preventing normal asset use. The copy is
localized in all 57 supported languages, long labels adapt to narrow rows, and
public unit prices stay visible when wallet balances are concealed. Native coins
no longer repeat the same network badge in asset pickers.

Switching wallets resets Home to the selected wallet's balance header. Same-wallet
balance updates retain the current scroll position. The existing backup-offer
appearance gate remains in place.

Wallet setup, settings, history, transaction details and WalletConnect review use
semantic directional symbols and layout. Universal completion and selection
checkmarks keep their native shape, correcting revision 4's forced mirroring.
Addresses and raw transaction data retain left-to-right presentation. Stellar
payment explanations follow the selected language while keeping identifiers
isolated and raw JSON copyable.

Tiny native balances, signed history amounts and below-cent send previews preserve
the mathematical meaning of their comparison signs in both writing directions.
Amount entry, atomic-unit conversion, authorization, signing and broadcast behavior
are unchanged by these presentation changes. This revision also includes the
already merged Solana nonce and response-context validation repairs, preserving
delegate-approval warnings and EVM command review.

Version remains **5.0.3 (105)** with **prerelease** status. Both `v5.0.3` and
`v5.0.3-build105` identify this update. Revision 4 remains available at
[`9ee9dd0`](https://github.com/OathWallet/oath-wallet/commit/9ee9dd08c8c9571b9396538527eacaef544b0e9d).
Its verification attachments are preserved; the new `revision5` attachments
identify this update and its checks separately.

## New and improved

- Address scans show the networks that actually validate the address, including
  network logos, localized guidance and bottom actions. Addresses retain
  left-to-right presentation in right-to-left languages.
- EVM send quotes reject stale or future-dated heads inside the provider fallback
  loop. A fresh fallback is chain-verified, and subsequent reads prefer it briefly.
  Transaction broadcasts are not automatically retried by this change.
- Story balance and history reads use the dedicated RPC and explorer path,
  preserving existing balances, activity identities and receipts. Celo history
  uses bounded pages and individual receipt checks.
- NEAR handles repeated indexed transaction versions only when their receipts
  agree, avoiding duplicate fees. Missing indexed balances remain unknown until
  checked against the contract. Rate-limited index reads respect Retry-After
  within a bounded retry budget.
- XRP can recover once when its rolling recent-history window advances before
  the first page is read. Existing pinned cursors remain exact.
- THORChain refreshes join cancelled history work before rotating its database
  generation. TON preserves the underlying failure and records it once.
- Restored wallets preserve legacy passphrase metadata when the passphrase is
  empty. Existing encrypted wallet formats remain readable.
- Optional TRON token labels and mixed Sei artwork catalogs are handled more
  accurately. Public-market TLS failures use cooldown without weakening TLS
  validation. Expected wrong-passcode and unavailable-biometric outcomes remain
  ordinary authentication results.
- Native status-bar delegation follows the visible screen on newer iOS versions.

Cronos balance, send, catalog and artwork infrastructure is included with targeted
tests, but Cronos remains disabled in the app. This prerelease does not advertise
it as an enabled network or claim account-wide RPC token discovery.

## Validation boundaries

Validation uses synthetic credentials, local fixtures and host tests. No live
transaction, physical device, simulator application or camera session was used.
The scanner harness does exercise CoreImage/Vision QR decoding on the Mac; it
does not establish the appearance or camera behavior of the iOS interface.

The ongoing [security review](https://github.com/OathWallet/oath-wallet-security-review)
retains its original source pins. These checks are not independent certification,
a completed audit, or proof of equivalence with Apple's distributed binary.
Historical tests do not automatically establish coverage for new changes.
